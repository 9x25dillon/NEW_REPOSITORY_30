## Key decisions

- **Use the real application.** Imported the existing Resonarium page and natal
  bridge from `astro-aae`, retained source attribution and AGPL text, and adapted
  its existing visual/audio surface. The sibling source checkout was not patched.
- **Keep the layers explicit.** Bedrock, optional overlay, trajectory and
  projection remain distinct. Disabling the overlay preserves underlying state.
  Natal inputs and audible tones do not modify device-physics constants in `src/`.
- **Distinguish supplied seeds from derived seeds.** Legacy JSON seeds are accepted
  as supplied. Newly derived seeds use BLAKE2b with an eight-byte digest and
  unsigned big-endian interpretation; arbitrary uint64 values travel as decimal
  strings. JavaScript Number is accepted only for safe integers.
- **Repair the calculation before extending its claims.** With intensity in
  mW/cm² and time in ms, fluence in J/cm² is I×t/1,000,000. Repaired pulse timing,
  circular phase averaging, audio phase handling and deterministic surrogate
  generation. Surrogate comparisons are model tests, not medical evidence.
- **Make survival construction use existing geometry.** Rotatable blueprints snap
  to the square lattice. Wards require tetragonal material; looms copy seated
  symmetry. Existing band-gap results determine ward discounts. Construction
  refusal consumes nothing, and utility structures are excluded from gun discharge.
- **Introduce an explicit expedition mode.** Three encounter stages augment
  existing world progression rather than replacing the game. Normal play remains
  available. The lightweight game oscillator is documented separately from the
  full experiment; full trajectory import is the route for using saved observations.
- **Keep personal payloads local.** The supplied raw tonal JSON and generated
  personal launch page are not part of the publication set. Public tests use
  synthetic or nonpersonal fixtures.

## Evidence and unresolved assumptions

Verification: all **404 TypeScript tests pass**; typecheck and build pass; the six
Python tests pass. Browser coverage includes Resonarium import/replay/audio/OFF
behavior, and Sonic Drifter's 14 upgrade checks, 22 battle checks and 14 expedition
checks. Desktop/mobile screenshots were inspected. The first full game suite
caught an obsolete eight-species assertion; it now covers eleven species and the
new species' contrast signs, and the full suite passed on rerun.

Still unresolved:

1. **Balance and readability under real play.** Short deterministic checks prove
   that mechanics operate, not that the economy, enemy pressure or forge remain
   satisfying after 30 minutes. Ask for an Xbox Elite Series 2 play report before
   tuning costs, charge rates or stage goals. Mobile layout fits, but that is not
   proof of comfortable touch play.
2. **Persistence.** Run state and selected import are held in page memory. Reload
   loses the run. A versioned save/restore design is still needed.
3. **Scientific interpretation.** Natal anchoring is a deterministic artistic
   mapping. Physiological transduction, therapeutic effects and biological meaning
   have not been established. AAFT on a tied binary sequence does not guarantee
   exact preservation of its spectrum; empirical significance is specific to the
   statistic and null used, and a failure to reject is not proof of no structure.
4. **Replay scope.** Python/browser experiment parity is tested. The small game
   model is a separate driver. Folding a uint64 into the game's uint32 seed permits
   collisions; neither seed equality nor this integration promises identical
   behavior across every platform, future version or human input sequence.
5. **Product scope.** The three stages are encounter layers, not three new maps.
   Imported trajectories currently loop stored observations rather than running
   the entire scientific engine inside the game.

## Vocabulary to use together

- **Invariant:** a property that must remain true through changes. Example:
  “Overlay OFF is an invariant: it must leave bedrock state unchanged.” Naming
  invariants gives implementation and tests a concrete constraint.
- **Provenance:** the traceable origin and transformation history of something.
  Example: “Record seed provenance: supplied uint64 versus derived BLAKE2b-64,
  plus the schema/model version.” This prevents visually similar outputs from
  being mistaken for equivalent experiments.
